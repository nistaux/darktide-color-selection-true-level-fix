# Register on class readiness and preserve rich suffixes across frames

The compatibility fix will use `hook_require` for the `HudElementNameplates` module and wrap the class's first `new` call. The wrapper calls DMF's preceding constructor chain first, allowing dependency-delayed hooks to register, and only then registers this mod's single late `hook_safe` on `HudElementNameplates.update`. This replaces ADR 0004's lifecycle assumption: live evidence showed that neither `on_all_mods_loaded` nor `StateGameplay` entry guarantees class availability.

Color Selection 2.15 removes True Level's first-line color and reset tags on later frames while True Level normally writes once per marker. The late safe hook therefore performs two phases across frames: it records a Rich Suffix Snapshot when True Level's formatted suffix is observable, then restores that exact suffix after a later destructive rewrite only when the current Color Selection-owned prefix remains usable and the cached and current suffixes satisfy a Visible Suffix Match. The cache is weak-keyed by marker, guarded by exact profile name and current player-record identity, and cleared when either guard changes, visible suffix content changes, the Activation Condition becomes inactive, or a new World Visit begins. This preserves current Color Selection player colors without reconstructing True Level formatting.

DMF 26.6.24 permits only one hook record per mod for a given target method, even across hook types. The adapter must not register both normal and safe hooks on `HudElementNameplates.update`; its one update-hook slot is the late safe hook. Class readiness, dependency hook ordering, first-frame snapshot capture, toggle reseeding, and per-frame restoration remain patch-sensitive and require in-game validation.
